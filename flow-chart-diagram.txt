[5] CHATBOT MESSAGE PIPELINE
--------------------------------------------------------------------------------
  User sends text (or taps a chip)
     |
     v
  push user bubble (list is inverted; newest first)
  setThinking(true)
     |
     v
  context.buildBotContext()                [store/wallet-context.tsx]
     parallel queries:
       month summary | today spent | yesterday spent | week spent
       last-month summary | category totals | biggest expense | tx count
     + closures addExpense()/addIncome() -> context.addTransaction
     |
     v
  interpret(text, botData)                 [lib/chatbot.ts]
     (intent dispatch - see [6])
     |
     v
  ~350 ms delay -> push bot bubble -> setThinking(false)
  (add intents mutate the DB immediately; summary numbers in the SAME reply
   are pre-computed, so confirmations state the post-add totals)

[6] CHATBOT INTENT DISPATCH TABLE (order matters - first match wins)
--------------------------------------------------------------------------------
  #  Regex trigger (lowercased input)              Response builder
  -- --------------------------------------------  ---------------------------
  1  ^add | ^log | ^record | ^track                ADD: parseAmount ->
                                                    findCategory ->
                                                    today/yesterday/tomorrow ->
                                                    addExpense / addIncome
  2  ^hi | ^hello | ^hey | good (morning|...)      greeting()
  3  thank | thanks | nice | great                 friendly ack
  4  help | what can you do | commands             HELP_TEXT
  5  left | balance | remaining | afford           leftReply() + allowance
  6  income | earn | salary | made | make          incomeReply(tf)
       (salary + no tf -> fixed salary line)
  7  spen|spent|pay|paid|bought|purchase|expense   see sub-branches below
  8  category word present                         categoryText(cat, tf)
  9  biggest | largest | most expensive            biggest expense line
 10  summary | overview | report | status          summaryText()
 11  per day | allowance                           dailyAllowanceLine()
 12  how many transactions                         count
 13  bare timeframe ("today?", "this month?")      spent/income for timeframe
 14  (none)                                        FALLBACK examples

  Branch 7 sub-order:
     a) category found AND "on" in text  -> categoryText (food/transport/...)
     b) biggest|largest|most|top         -> biggest expense line
     c) else                             -> spentFor(tf || this-month) + left

  Timeframe detection (detectTimeframe), first match wins:
     today/tonight -> yesterday -> (this|the) week -> last week ->
     last/previous month -> this month | month | so far

  Amount parsing (lib/money.ts parseAmount):
     "5000" | "1,234" | "5k"=5000 | "1.5k"=1500 | "2m"=2,000,000
  Category synonyms (lib/categories.ts):
     e.g. lunch/coffee/grocery->Food  bus/taxi/fuel->Transport
          rent/wifi/electricity->Bills  salary/wage->Salary  ...

--------------------------------------------------------------------------------
[7] MONTH SUMMARY / BUDGET CALCULATION
--------------------------------------------------------------------------------
  getMonthSummary(db, month)                 [lib/wallet.ts]

    fixed = SELECT amount FROM fixed_income WHERE month = :month
            |
            +- found -> use it (per-month override)
            +- none  -> settings.fixed_income_default

    extra = SELECT SUM(amount) FROM transactions
            WHERE deleted=0 AND type='income'
              AND substr(date,1,7) = :month

    expense = SELECT SUM(amount) FROM transactions
              WHERE deleted=0 AND type='expense'
                AND substr(date,1,7) = :month

    income  = fixed + extra
    left    = income - expense

  Consumers:
    Wallet card ("Available budget", chips, allowance footer)
    History tiles + "Budget used %" bar
    Chatbot (summary/left/income answers)
    buildBotContext (all money answers)

--------------------------------------------------------------------------------
[8] THEME (DARK/LIGHT) FLOW
--------------------------------------------------------------------------------
  Settings tap: System | Light | Dark
     |
     v
  context.setThemeMode(mode)                [store/wallet-context.tsx]
     |
     +--> applyTheme(mode)                  [lib/theme.ts]
     |      resolved = mode=="system"
     |                  ? Appearance.getColorScheme() ?? "light"
     |                  : mode
     |      colorScheme.set(resolved)       (react-native-css observable)
     |      ==> every "dark:" class re-evaluates instantly
     |
     +--> setResolved(resolved)  -> StatusBar light/dark
     +--> persist settings.theme
     |
     v
  watchSystemTheme (registered at boot):
     OS theme flip -> applyTheme(currentMode) -> setResolved()
     (so an explicit Light/Dark choice survives OS flips;
      "system" naturally tracks the OS)

[9] DATA MODEL (SQLite - local only)
--------------------------------------------------------------------------------
  +---------------+     +---------------+     +----------------+
  | transactions  |     | fixed_income  |     | settings       |
  +---------------+     +---------------+     +----------------+
  | id        PK  |     | month     PK  |     | key        PK  |
  | uuid      UQ  |     | amount        |     | value      NULL|
  | type (i|e)    |     | updated_at    |     | updated_at     |
  | amount        |     +---------------+     +----------------+
  | category      |            ^   keys: currency, theme,
  | note  (NULL)  |            |         fixed_income_default
  | date          |            |
  | deleted       |     month override of
  | created_at    |     the default salary
  | updated_at    |            |
  +---------------+            |

  Relationship (logical):
    fixed_income(month) .VS. substr(transactions.date, 1, 7)
    -> summary(month) = fixed_income OR default  +  income txs  -  expenses

  All data lives only in the app sandbox (wallet.db) on this device.
